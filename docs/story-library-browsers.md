# Story Wizard and Created Content

The Narrative Viewer's **Created Content** browser has an explicit **Game / Database** source switch above search. Game lists current narrative entities (including genuine nested entities) and game conversations, excluding character-input/framework trees. Picking a Game card opens its existing game record. Each Game card has a small trash button that dispatches only a game deletion action; the browser stays open and counts update. Root and nested deletion use the existing graph cleanup and undo paths. Database lists the permanent created-content library and retains independent copy insertion into the game. Database cards never receive a delete callback or trash control, so this browser cannot delete database records. The main Library's own Created Content page is unchanged.

Story Wizard is the single reference browser in the Narrative Viewer, Master Act story lane and Library / Story & Narrative. The former separate Story Tools button has been removed. The combined catalogue offers Frameworks, Concepts, Story structures and Supporting templates. Frameworks/concepts have **Start wizard**, **Add to canvas** and **Information** actions. Structures and supporting templates offer direct insertion and information, without an invented wizard. Master Act and nested canvases retain their previous omission of supporting subnode templates. Character/group-targeted input wizards remain focused on guided framework/concept inputs.

Direct insertion closes the catalogue and uses the canvas it was opened from. The main Narrative Viewer and Master Act retain their existing insertion paths; generic nested canvases and the master Library use a shared, tested insertion helper. Opening Story Wizard from the master Library adds to the current game's Narrative canvas, matching the wizard's existing save-to-game behavior. References are not edited by insertion, and developing content stays in the separate Created Content browser. Unsaved wizard answers require confirmation before a direct insertion discards them.

**Library · Master Database → Created Content** is also a dedicated sidebar entry directly below Physical. It opens a full-page catalogue using the same categories, search, counts and saved records as the existing Story & Narrative → Created Content button. The button remains available. The sidebar count includes created products only, excluding reference frameworks/concepts. Selecting a saved product opens its existing Library editor/inspector; conversation templates open their Library script editor. Neither entry duplicates or moves data.

**Library → Physical** uses the same left category sidebar and search, with All content, Items & Gadgets, Locations and Sensor hardware. Each section retains its own creation button; item-type filters remain above the item cards, including when a filter has no results. Empty physical categories remain accessible for adding their first record. Selecting a card still opens the existing master-template inspector.

Physical and Created Content share `LibraryAssetCard`: the same grid sizing, image proportions, dark photo background, neutral panel, dashed violet library border, caption spacing and selection treatment. Created Content uses its saved portrait/image or a category symbol above its name and content type; longer descriptions are available on hover and in the existing editor. This applies to both full-page and modal Created Content browsers. Story Wizard retains green/brown reference cards and framework/concept symbols, with blue story structures and violet supporting templates.

Both content browsers use matching blue-tinted card, photo, browser and category-pane backgrounds. The category header has a **Hide categories** button, which folds the pane into a narrow rail with **Show categories** to reopen it. The selected category, search text and item-type filter remain in place while the pane is hidden. The same collapse controls are available in modal Created Content browsers.

Each card in Story Wizard has an **Information** button. Frameworks open the same full reference dialog as the master Library, including the diagram, recommended uses and explanations. Concepts, structures and supporting templates open a read-only description, original tree overview and reference parts/questions where present. Closing the reference or pressing Escape returns to the existing catalogue and restores focus to Information, preserving its search, purpose filters and answers. Reading information does not select a source or launch a wizard.

- **Story Wizard** contains the reference frameworks, reusable concepts, story structures and supporting subnode templates. Frameworks and concepts reuse the shared vector emblems. Story structures use the structural emblem. The main Library framework, concept and structure catalogue cards also show these emblems.
- **Created Content** contains saved characters, narrative places, groups/institutions, items, conversations, Story Beats/acts and developed story plans. A left category pane filters All content, Characters, Story Locations, Groups & institutions, Story Items, Conversations, Story Beats & acts, Developed story plans and Other saved content. Older Events and Quests appear under Story Beats & acts. Categories stay visible when empty, with counts that follow the current search. Cards show saved images where available. The empty state explains how to populate the browser by saving narrative work to the library.

`narrativeLibrary.js` provides shared, display-only classification. All saved narrative node templates are content; subnode templates appear in **Saved node templates**. The Story Wizard retains its existing supporting-template insertion shortcut. Concepts with saved wizard sessions or session history are developed content, while reference concepts (including custom reference concepts) remain tools. Story structures default to tools. Explicit `libraryRole` choices still apply to other records. Browsing does not rename, move, duplicate or rewrite existing records and does not change persistence schemas.

The Narrative Viewer node palette has three compact rectangular category buttons styled like the Mechanics Viewer work areas: **Base Nodes**, **Subnodes** and **Supporting**. Base Nodes opens by default. Selecting another category replaces the visible list; clicking the selected category keeps it selected. The All and Templates filters are removed; saved templates are accessed through Created Content. Supporting subnodes are listed only in Supporting, avoiding duplicate palette entries. The refreshed appearance is permanent throughout the app; the old appearance toggle and its stored off preference no longer affect the interface. Palette selection and focus mode remain available.

Selecting a Created Content record in the master Library opens its existing editor/inspector. Selecting it in the Narrative Viewer or Master Act inserts a copy using the existing template paths, preserving editable wizard answers and graph data. Master Act's story browser omits supporting subnodes, matching its existing insertion support. Generic mechanics/task browsers keep their existing content and icons.

Conversation templates use their own library.conversationTemplates collection. A Library pick opens the master script; a Narrative Viewer or Master Act pick creates a detached planned project conversation and opens it, with speaker names retained for explicit profile assignment. It does not create a canvas node. Direct Conversations buttons are available inside the Narrative Viewer and Story & Narrative Library; there is no separate main navigation page.

Tests cover reference/content classification, catalogue coverage, independent wizard/information/insertion actions, original collection routing, root and nested reducer insertions, read-only reference details, portrait cards, Physical category/type/search filtering and independent editable character/place insertion. The local browser is also checked for catalogue filters, information dialogs, Dragon workshop launch, direct FATE insertion followed by undo, category switching and matching Physical/Created Content presentation.
