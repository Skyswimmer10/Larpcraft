# One character, several editable inputs

Select a Character on the Narrative canvas or inside a Master Act. The Character inputs panel uses the existing Character node type.

Character canvas cards show a Description button in place of the full prose. It opens a centered, nearly full-height reading dialog, up to 1600px wide. A portrait area and filled name/title, story role, gender, race, age, goal/motivation and relationships occupy a separate sidebar beside the complete prose. Empty details are omitted. A saved node image appears uncropped in the portrait area; otherwise the space stays reserved for a photo or illustration. Portrait/details and prose scroll independently on desktop, while smaller screens stack the sections. Adjacent green framework and brown concept badges reuse the Story Wizard symbols and identify their sources on hover and for screen readers. Only included inputs appear, with one badge per source even when several sessions use it; saved missing-source snapshots retain their identity. This shared presentation also applies in nested canvases. Descriptions, saved node dimensions and inner-canvas navigation remain intact.

- Add a framework or concept to start its wizard for this character. Every source is optional. Each saved version has its own Edit wizard button and retains its answers, purpose and context.
- The small red trash button beside each inspector input deletes that specific saved input, its questions, source passage and inner-canvas tree. The checkbox still only includes/excludes it. Deletion is one Undo action and does not delete shared canvas references or library originals. Drafts tied to the exact removed session/character/scope are cleared. Independent character facts, images, other sessions and personal writing stay in place; exact source passages in a manual combined description are removed, while independently rewritten text remains protected.
- The Story Wizard browser identifies its 12 frameworks and 44 existing concepts with simple vector emblems on green framework / brown concept cards. Symbols inherit a single ink color, retain identity for copied or renamed references, and leave the authored library artwork unchanged. New concepts without a known reference receive a symbol for their category.
- Double-click a character to open its inner canvas. Each saved framework/concept session has its own card, including separate uses of the same reference. Frameworks are green and concepts orange; cards show their contribution and an inclusion checkbox. Edit this framework / Edit this concept resumes that character's exact session. The header adds further sources to the containing character.
- Open an input card to see its filled nodes. Concepts retain the original native tree, roles, nested nodes, images, edges and layout, with wizard answers attached to the corresponding nodes. Answers without a native counterpart appear alongside the tree as answer cards. Frameworks show their reference and answered questions. Editing a native answer updates the parent wizard and character text in the same undo transaction. Wizard saves update those same nodes while preserving layout, extra nodes and connections.
- Existing characters materialize the input canvas when opened. An older flattened concept tree moves into its input card as a unit when this would not cut connections; otherwise its existing nodes and connections stay in place. Deleting an input card hides its canvas view while retaining the saved input; Show hidden inputs in the header restores it. Inclusion in the description is controlled separately.
- Use a canvas input to explicitly accept an existing concept or framework in the same graph. A visible connection is added. Editing a developed input updates the character in the same save/undo transaction. Cutting its connection removes that contribution; deleting its source retains a saved snapshot.
- New wizard-created characters combine their inputs automatically. Existing characters opt in with Combine into a living character description. Existing body/description wording is retained, including older records whose two fields differ.
- The game inspector starts with Name/title, Story role, Gender, Race, Age and one brief Goal/motivation. All are optional; roles have suggestions and allow custom values. Existing roles and goals supply initial values without rewriting saved data.
- Add image in the selected character inspector stores a local uploaded image on that character. Its square portrait appears immediately above Name/title, with Change image and Remove image controls. The full description window uses this same saved image in its reserved portrait space. Image changes use normal graph saves and undo and travel with independent library templates.
- Character, Group, Story Item and Story Location canvas cards scale their saved image to the available body using object-fit: contain. Description overlays the upper left. Included framework/concept symbols occupy a separate 64px rail on the right, which scrolls vertically when needed. Removing or excluding the last source removes the rail and returns that room to the image. Saved node dimensions, aspect ratios and detail-graph navigation are preserved. Items retain their build-status badge; their Description window exposes player lore and complete facilitator lore separately. Mechanic-specific item cards keep their existing presentation.
- The full description sidebar includes named framework/concept symbol buttons below the portrait and basic details. Each saved use opens its exact completed questionnaire in an editable wizard over the description; saving returns to the updated description. Repeated uses stay distinguishable. Main and nested game canvases pass their containing graph scope so edits reach the correct character. Linked inputs edit their original source, and retained missing-source snapshots direct recovery through the existing inspector. Library draft canvases do not target similarly named game characters.
- Relationships and loyalties are categorized short names (Loyal to, Enemies, Friends, Siblings, Family, Allies, Rivals). They can refer to a character in the same graph or a game team/faction, or just contain a name. Links follow renamed records; missing records retain their last name. These references describe relationships, not story-flow edges.
- Each compact input card identifies its saved title and framework/concept, with its Edit wizard control between the inclusion checkbox and red trash button. Linked inputs with several sessions retain separate named editor buttons. There is no Compare inputs section or duplicated passage prose in the inspector. Protected passage revisions remain reachable through a Review passage update button when needed.
- Edit Character’s Profile opens a centered writing window matching the large description window: up to 1600px wide and nearly full-height. It contains Character profile, Voice and dialogue, Saved questions and Earlier writing tabs. The profile page has full-profile, short-introduction and AI dialogue/story-context format choices at the bottom, alongside Copy text and Download text. Full profile remains editable; the other formats display derived text without overwriting the saved description. There is no separate Export tab or duplicate inspector Voice/Export buttons. Saved questions starts with framework/concept symbol buttons and counts. Selecting a source reveals only that source's complete prompts and editable answers, combining repeated uses of the same source while retaining session labels. Personal questions retains older/unassigned questions and allows new ones. Excluded inputs keep their saved questions accessible. Earlier writing retains populated native notes and older selections; empty background/personality/secret fields no longer clutter the inspector. New background and personality work belongs in concepts/frameworks. The old generic Types & Options selector is absent from game character inspectors. Library template editing is unchanged.
- Archetype & Dark Sides keeps its existing behavior but appears in the game inspector only while an accepted masculine-archetype framework contributes to the character. Excluding the framework hides the controls and their generated contribution; authored dark-side values and existing canvas nodes remain stored. Character gender does not restrict which frameworks can be used.
- Untouched paragraphs update automatically when wizard answers are saved. Full-description edits track paragraph ownership: paragraphs added by the author stay independent, while rewritten or deleted source paragraphs are protected. Changed inputs show only affected paragraphs, with current wording beside the proposed revision and Use this revision / Keep my wording / Edit this paragraph controls. Choosing a revision replaces that paragraph without dropping independent additions. Blank lines separate paragraphs; adding words within a source paragraph protects that whole paragraph. Ambiguous merges/splits preserve authored prose and retain deleted-source markers for later review. Prose edits never infer or overwrite questionnaire answers. Older whole-description overrides are converted conservatively during profile reconciliation. Accepted generated passage revisions remain stable even when a wizard retains its own older output override. Normal graph Undo restores source and derived description together.
- The profile page's output selector offers a short introduction, full profile (brief facts plus description), or AI context (facts, description, companion voice writing and existing authored notes). Original wizard questions and answers are an opt-in checkbox for AI context; their framework names are retained. Secrets remain writer-only context, and possibilities, unanswered questions and tensions are labeled separately from established facts. Copy/download derives from current saved state. There is no external AI call. Prose formatting combines recorded text and existing local framework formatters; it does not invent connective story facts.
- Saving a character to the library creates an independent template, preserving editable wizard records and frozen concept references. Canvas input links become saved copies. A missing or detached developed input can become an editable local character input. Copying a character with its inputs remaps those links; inputs outside the selection become independent saved copies.

## Optional quick attributes

Characters have a single compact Quick attributes button in the inspector and editable profile. It opens a centered window for all tag/text editing; no description, disclosure toggle, or field list occupies the inspector. This is an independent, optional way to define a character without completing a wizard. Authors can use attributes alone, frameworks alone, both, or neither. No traits are selected by default.

Manage attributes opens a centered dialog with Personality, Appearance, Skills & interests, Custom, and Selected categories. Choose which fields to show, then apply the selection. Unchecking a field removes its values only when applied; Cancel retains the original data, and graph Undo can restore an applied change. Suggested tag sets cover personality, strengths, flaws, Enneagram-inspired roles, virtues, physical signature, clothing, mannerisms, skills, and interests. Appearance note is short text. Authors can enter their own tags or create custom tag/text fields. These labels are writing choices, not assessments. Existing brief identity and relationship fields remain separate.

Only populated fields appear in the description window and full/AI text exports. The short introduction uses attributes as a fallback when there is no longer description. The canvas card shows up to three tag previews plus a remaining count. Attributes never modify wizard answers or protected prose, and wizard edits do not infer, replace, or reconcile tags. If two inputs disagree, the author can edit either; no silent priority rule resolves that disagreement.

`characterAttributes: { version: 1, fields: [...] }` is optional node data. Each field stores `id`, `label`, `category`, `kind` (`tags` or `text`), and `values[]` or `value`. Normal JSON save/reload, library templates, clipboard copies and graph undo preserve it. Missing attributes require no migration or bulk data rewrite. The implementation is character-only.

## Data and compatibility

An adjacent compact Media & references button opens an optional ordered gallery. `mediaGallery[]` stores images, video URLs, external file-path references, titles, captions/timing notes and credits. The existing portrait stays independent unless Use as portrait is selected. `researchIds[]` links the character to reusable library references. These links open the same editable library records; unavailable references remain visible and can be unlinked. The editable profile has the same controls, and the full-description viewer offers read access when media/research is present. Gallery metadata, not binaries, is included in AI context exports. See [research-and-media.md](research-and-media.md).

characterCanvas opts a character into nested input views. Each child characterInput identifies a canonical parent session (or an existing live canvas link); attachedChildId binds the session to its view. Children do not carry duplicate independent wizard sessions. Generated-answer baselines distinguish native edits from subsequent wizard saves. These additive fields travel through normal JSON persistence and clipboard/template copies; opening a character performs the local conversion rather than rewriting every saved game on startup.

The optional characterFacts field stores brief identity/role/goal values and typed relationship references with name snapshots. characterProfile stores accepted links/snapshots, inclusion choices, existing authored details, companion performanceText, passage provenance and manual overrides. Existing narrativeWizard / narrativeWizardHistory records keep the complete editable wizard sessions. Generic concept sessions retain sourceSnapshot, so later template changes or deletion do not alter their original reference. All wizard save paths preserve this metadata, and reducer reconciliation handles ordinary, nested, Master Act and task graphs without crossing scopes. Clipboard copies remap included relationship targets; external targets detach to short names in standalone templates. No bulk rewrite of canonical project/library data or seed reset is performed.

characterProfile.descriptionParagraphs stores source ownership, generation baselines, authored wording and pending paragraph revisions. It travels with copied profiles and persistence, and remaps linked source keys with their inputs. The full description remains one editable text area. Source deletion through its trash button removes its owned paragraphs and answers; independent authored paragraphs stay. Group descriptions now use the same paragraph protection and shared profile controls, with group-specific facts and output labels.

Voice and dialogue now has a collapsible voice-notes area and shared conversations involving the character. The main navigation also has Conversations. See [conversations.md](conversations.md) for script editing, participant links and selected AI context exports.

## Validation

Regression tests cover multi-source continuation, duplicate titles, conditional trait changes, preservation/review of manual writing, direct answer edits, template isolation, missing sources, cut connections, scoped repeated node IDs, facts, typed relationships and rename/undo, clipboard remapping, framework gating and opt-in questionnaire exports. A real local-middleware test saves into a unique temporary directory, reloads through migration and verifies editable sources, facts, relationship names, voice text and exports; it does not touch authored files. Server-rendered component tests check source editor routing, compact facts, full prompt visibility and larger writing views.

Interactive browser verification was unavailable because browser automation access to the local URL was blocked by the browser tool's URL policy. Local HTTP health and Vite component transforms are checked separately; this is not a claim of visual browser verification.
