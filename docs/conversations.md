# Conversations and character voice

## Goal Compass writing desk

The conversation editor uses a dark green glass style with translucent gradients and a wide three-pane layout. The editable conversation title and story status sit in the top bar. The left pane starts with larger participant portraits, followed by author goals and a location card. Drag the divider beside either side pane to resize it; the center dialogue area adjusts. The inspector ranges from 260px to 640px, subject to available width, while both dividers preserve at least 280px for dialogue. Both support arrow keys, Home/End and double-click reset. Dragging the inspector divider left expands the inspector. Resizing is presentation-only and never modifies script content. The divider supports arrow keys, Home/End and double-click to reset. Width limits keep the dialogue usable, and resizing does not modify conversation content. Add participants through one searchable character/name picker and one Add button. Type to filter existing characters, or use its dropdown to browse. Selecting a result stages that scoped character; press Add to include them. Type a new name and press Add to create a name-only speaker. The selection hint distinguishes linked characters from names. Existing characters already in the exchange are omitted from the choices, nested graph paths disambiguate matching names, and keyboard arrows/Enter select a result. Library templates accept names without binding to game profiles. The narrow scene strip above the conversation preserves the existing context field. The center scrolls independently and shows compact left/right dialogue with 33px portraits vertically centered beside each bubble and brighter, distinct speaker colors. A tiny arrow beside each spoken message toggles that individual bubble into the center and back to the speaker’s normal side. Centered spoken messages retain their portrait, name and speaker color; narration remains visually separate with a subdued dashed treatment. A third participant does not default to the center. Choose a message to edit its words, speaker, line tags or order in the right inspector. A composer adds new lines, with Ctrl+Enter as a shortcut, and an editable summary stays below the transcript.

The inspector shows the selected speaker’s image in a 104px square, keeping the whole uploaded image visible. It reads the portrait, attribute tags and brief description from their live character profile. Optional line tags appear as small italic text beneath the words in spoken bubbles. Empty tags leave the bubble unchanged. Three colored goal columns sit side by side, initially called Survival, Trust and Mission. Both headings and goals can be edited per speaker for this particular conversation. They are optional and do not overwrite the character's overall motivation or framework answers. The goal cards use compact icons and two-row answers while retaining the three columns. A compact speaker ribbon provides Left/Right arrows, profile linking, a dialogue alias, reference and safe removal. Add passage, Add stage directions, reorder and remove actions sit under the selected message, including stage directions. The detailed character reference opens from the ribbon.

**Edit icon** controls appear beside the conversation heading, on the selected participant's portrait in the inspector, and above each goal heading. Choose a built-in symbol, upload an image, remove the icon, or restore its default. Removed icons retain an **Add icon** control in the editor. Participant overrides affect the roster, transcript and inspector together and do not alter the underlying character's image. A default participant portrait continues to follow its linked character. Conversation icons also appear in conversation lists and saved-content cards. Uploads and explicit removals travel with reusable library copies and normal project saves.

Icon fields are `conversation.icon`, `participant.icon`, and `participant.goalIcons[goalId]`. An absent value inherits the default; `null` explicitly removes the icon; `{ symbol }` selects a built-in symbol and `{ image }` embeds an uploaded image file. Library icon/image/visibility metadata follows edits to the template.

Optional additive fields are `authorGoals`, `summary`, `location` (scoped reference and snapshot), `locationNotes`, participant `goals`, `goalLabels`, `side`, `sceneName`, `profileSnapshot`, and passage `tags` and optional `position: "center"`. Centering is stored per passage, preserves the speaker’s normal side, and travels with saved scripts and library copies. Older scripts open without a migration or invented answers. Linked location names and character details read live; location notes belong to the conversation. Reusable templates retain portraits, profile context, goal headings/values, location snapshots and script metadata while removing character and location bindings. Imports remain independent planned copies. Copy/download includes the optional author goals, location, speaker goals and summary.

**Name in dialogue** is an optional conversation-local alias (`participant.sceneName`). It changes this speaker’s bubble labels throughout the exchange, without renaming their roster entry, inspector heading, speaker choices or linked character. Clearing it restores the canonical name. Copy/download uses dialogue aliases for spoken lines and includes a canonical-name-to-alias key. Aliases survive profile renames, saves, backups and reusable library copies. Existing names are preserved; no old script is rewritten.

A linked location displays its image in the left pane. Story Locations use their own image first, then the image of their linked physical location. Live linked records update the panel; detached library copies retain a location snapshot.

The browser reuses LARPCraft’s database gallery: a full-width search toolbar, a New conversation action, and a collapsible Story status sidebar with counts. Cards are 104px high (previously 224px), with compact portrait clusters and a single-line scene preview; hover reveals the full title, participants and scene. Cards show the conversation icon, participant portraits, title, speakers, scene preview, status and passage count. Duplicate introductory headings and explanation text are omitted. The same browser works for game scripts, character conversations and library templates.

Open **Narrative Viewer → Conversations** to browse the active game's shared scripts in a large dialog over the canvas. The former separate Conversations navigation page is removed. The button is also available inside nested narrative canvases. A character's **Edit Character’s Profile → Voice and dialogue** shows their voice notes separately from the conversations they participate in. New conversation from that profile preselects the character. Opening a script from any participant or the narrative browser edits the same project record. Done returns to the previous screen.

Each conversation has a title, optional context, participants and an ordered sequence of speaker-labelled passages. Speakers can link to existing characters anywhere in the game, including nested Master Act story lanes, or remain names without profiles. A name-only speaker can be linked to a profile later. Narration/stage directions has its own speaker option. Passages can be added, reordered and removed. A participant with passages must have those passages reassigned or removed before removing the participant.

Conversations default to **Planned script**. The author may mark an exchange **Happened in the story**. This distinction is retained in copied text and AI context. Participation never establishes friendship, allegiance or other relationships automatically. Existing brief facts and relationships are available as reference.

The profile's AI dialogue/story output offers an opt-in checklist of this character's conversations. Only selected exchanges are included. Conversations never become part of the enduring character description. Voice notes preserve the existing performance text, including older voice notes.

Game data lives once in project.conversations, with no duplicate scripts on character nodes. Participant references contain the root graph collection, complete parent path and character ID. Matching IDs in different graphs cannot collide. Names follow renames and retain a snapshot if a character is deleted. Copying or importing a character does not silently enrol it in the original character's conversations.

**Save conversation to library** creates an independent reusable snapshot in library.conversationTemplates. The script, context, speaker names, narration and recorded status are preserved. Project character links become names, using their latest saved names; no game profile references leak into a reusable template.

Open **Library → Story & Narrative → Conversations** to browse, create, edit or delete templates. The same templates appear under **Created Content → Conversations**, including its category count and search. Selecting a template in the Library opens its master editor. **Add copy to current game** opens a detached game copy with planned status and lets the author assign speaker profiles explicitly.

Selecting a saved conversation from Created Content in the Narrative Viewer or a Master Act story lane also adds an independent planned game copy and opens it for editing. Matching names/IDs never select characters automatically. Template edits, game edits and deletion affect their own store; normal Undo works independently in both. Reusable copies do not inherit established-history status from a previous game.

Existing project/library persistence and complete workspace backups carry active conversations and reusable templates separately. Additive migrations supply empty collections for older files. Normal Undo covers conversation and template creation, edits and deletion. Standalone character library templates do not carry the game's shared conversations.

Tests cover shared access, scoped identity, name-only speakers, rename/deletion, Undo, explicit AI inclusion, story status, rendered controls, detached template copies, master/game isolation, library category routing, workspace transfer and a real project/library save/reload against the local data middleware in an isolated temporary directory.


## Floating portraits and message ribbons

Hover or keyboard-focus a portrait beside a message to see an enlarged floating profile with its canonical name and up to three traits. The preview sits beside the portrait and flips/clamps at the dialogue pane edges; it does not resize any pane or change the selected passage. Click the portrait or use the pin button to keep it visible. Close or Escape dismisses it; Escape leaves the conversation open. Unpinned previews dismiss when focus/pointer leaves or the transcript scrolls. Conversation-specific portrait overrides and explicit icon removal are respected.

Only the selected message has a small action ribbon beneath its bubble: move up/down, add a passage, add stage directions and remove the selected passage. These controls also work on narration. The former Speaker settings disclosure is replaced by a compact inspector ribbon with a dialogue alias, link, reference, safe participant removal and Left/Right arrow toggles. Alias, profile and reference buttons reveal one compact detail field at a time. Alias edits still affect dialogue labels only; changing side affects the participant’s normal side, preserving individual centered passages. Add-passage/stage controls remain available in the inspector when no passage is selected. These are shared game/library editor views and require no data migration. Visual PDF excludes the editing ribbons and floating preview while retaining message portraits.

## Conversation exports

The middle toolbar has one Export menu. Visual PDF downloads an A4 image-based document with the full transcript, conversation icon, portraits, speaker colors, left/right/center placement, optional italic tags, scene and summary. It excludes both inspector side panes, the composer and editing controls. Normal bubbles stay together; an oversized bubble continues at text-line/portrait-safe boundaries. Rendering uses bounded page canvases instead of a single giant image and loads PDF dependencies only when requested.

Screenplay text (.txt) uses uppercase speaker cues above narrower indented dialogue, with stage directions as separate action paragraphs. It follows live character names and dialogue aliases, retains Unicode text, and omits pictures, analytical tags, author goals and profile notes. Conversation notes (.txt) preserves the earlier full-context text export. All exports are downloads; they do not alter the game or library.

New relationship selections offer story entities only. Real-world teams and players are excluded; existing saved team relationships remain resolvable.

In the character inspector, Quick attributes uses a square symbol button with an adjacent label. Media & references sits after development/framework controls, immediately above Box Size, for root and nested character nodes.
